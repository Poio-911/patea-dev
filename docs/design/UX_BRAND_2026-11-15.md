# Pateá: una cancha compartida

15 de noviembre de 2026.

La identidad parte del fútbol amateur uruguayo: el encuentro con el grupo, la cancha de barrio y el próximo partido. La fotografía aporta ese contexto; los datos deportivos y las acciones conservan el protagonismo. Se mantienen los temas Cancha y Claro, sus colores semánticos y el contraste de texto.

## Cambios de experiencia

- Acceso con fotografía editorial, formulario despejado, ingreso y registro distinguibles, validación, autocompletado y recuperación de contraseña funcional.
- Panel con saludo, acción para armar partido o crear grupo según contexto, convocatoria fotográfica y acceso explícito al vivo. Las camisetas y los datos siguen usando la información del partido.
- Splash, cabecera y navegación con una firma de marca coherente. Tooltips, estado seleccionado anunciado y animaciones breves que respetan movimiento reducido.
- Creación y edición de equipos con acciones más claras, junto con las mejoras funcionales del asistente y los estados de carga, vacío y error.
- Página sin conexión autónoma: marca oficial, fondo azul marino, acción volt y reintento real. Sin fuentes, fotografías ni recursos de red necesarios para mostrarla.

Los nuevos recorridos de acceso, panel y cabecera se verifican en los dos temas a escala de texto 1,3×. Las capturas de revisión se generan aparte de los masters; un cambio visual requiere revisión antes de actualizar goldens. No se representan funciones simuladas como si fueran servicios reales.

## Fotografía y procedencia

La imagen fue generada con la herramienta integrada **image_gen** para esta mejora de Pateá. No es una fotografía documental de personas, una cancha o un evento identificados.

Archivo de entrega: `patea_matchday.webp`, **1536 × 1024 píxeles**, aproximadamente **137 KB**. Se incluye en `patea_mobile/assets/brand/` y `public/brand/`. La compresión WebP mantiene la composición original y permite compartir el recurso entre web y Flutter.

### Descripción completa de generación

Esta es la descripción de generación conservada, no una transcripción literal del prompt original:

> Fotografía editorial de una cancha modesta de fútbol cinco en Montevideo a la hora azul. Césped sintético gastado, una línea blanca diagonal, alambrado, focos suaves y un barrio bajo de fondo. Dos adultos de espaldas, situados en el tercio derecho; uno lleva una pelota bajo el brazo. Ropa azul marino y una pechera amarilla, sin marcas. Dejar espacio oscuro a la izquierda para texto blanco. Cuerpos naturales, grano fino, sombras verdeazuladas y luces cálidas. Sin texto, logos, marcas de agua, interfaz ni trofeos. Encuadre adaptable a composiciones 3:2 y 16:9.

El recorte de cada pantalla conserva a los jugadores a la derecha. El texto usa un velo oscuro independiente del tema para seguir siendo legible. La foto no se usa para reconstruir ni reemplazar el logotipo.

## Marca oficial y regeneración

La fuente vectorial es `patea_mobile/assets/icons/logo_patea.svg`. Se preservó su trazo oficial; sólo se normalizó el `viewBox` para evitar el corte del pie. `PateaBrand` reúne el símbolo y el nombre en Flutter. La versión web del símbolo está en `public/brand/patea-mark.svg`; la página offline incorpora ese mismo SVG para funcionar sin una descarga adicional.

Los iconos de iOS, Android, escritorio, PWA y favicon se derivan de ese vector. El icono de App Store se exporta opaco. No se generó un logo con IA ni se dibujó otro símbolo para sustituirlo.

Desde la raíz del repositorio:

```sh
npm run brand:assets
npm run brand:check
```

El primer comando regenera los derivados de marca mediante `scripts/generate-brand-assets.mjs`. El segundo ejecuta las comprobaciones de tamaños, formato y consistencia. Para optimizar también una nueva imagen de referencia autorizada, el generador admite su ruta como argumento:

```sh
npm run brand:assets -- /ruta/a/la/fotografia.png
```

Las fuentes y los derivados deben revisarse juntos. Una actualización de marca no debe introducir claves privadas, credenciales ni archivos generados de compilación.
