# 13. Sistema de Evaluaciones

## Resumen

El sistema de evaluaciones permite a los jugadores evaluar a sus compañeros después de cada partido. Es el motor principal de progresión de OVR (Overall Rating) y atributos individuales. Soporta tres modalidades de evaluación: **puntos**, **tags de rendimiento** y **texto libre con análisis IA**.

---

## Tipos de Evaluación

### 1. Points (Puntos)
- Rating numérico del 1 al 10
- Afecta el OVR general del jugador
- Se distribuye proporcionalmente a los 6 atributos según la posición del jugador
- Es el tipo más directo: rating > 5 sube OVR, rating < 5 lo baja

### 2. Tags (Etiquetas de rendimiento)
- Etiquetas predefinidas con efectos en atributos específicos (`PerformanceTag.effects[]`)
- Cada tag tiene un `attribute` y un `change` (positivo o negativo)
- Aplica **diminishing returns** según el valor actual del atributo
- No afecta el OVR directamente, sino atributos individuales que recalculan el OVR

### 3. Text (Texto libre con IA)
- El evaluador escribe una descripción libre del rendimiento
- La IA (Gemini) analiza el texto y extrae `aiAttributeChanges[]`
- Cada cambio tiene `{ attribute, change }` similar a tags
- Aplica **diminishing returns** (misma fórmula que tags)
- También guarda `aiSummary` y `aiConfidence` para referencia

## Algoritmo de Asignación de Evaluaciones

**Archivo**: `src/hooks/use-match-actions.ts` → `generateEvaluationAssignments()`

### Proceso

1. **Filtrar jugadores reales**: Solo jugadores con `id === ownerUid` pueden ser evaluadores
2. **Fisher-Yates shuffle**: Se randomiza el orden de evaluadores con shuffle uniforme (no `sort(random)`)
3. **Para cada evaluador**, se seleccionan 2 jugadores a evaluar (MAX_PEERS = 2)

### Criterios de selección (sort de candidatos)

| Prioridad | Criterio | Descripción |
|-----------|----------|-------------|
| 1 (Primary) | Incoming Count ASC | "Starve the Rich" — prioriza jugadores con menos evaluaciones entrantes |
| 2 (Secondary) | Teammate Priority | Compañeros de equipo tienen prioridad |
| 3 (Tertiary) | Stable | Respeta el orden del shuffle original (sort estable) |

### Fallback sin equipos

Si el partido no tiene equipos (`match.teams` undefined), las asignaciones se generan igualmente pero sin teammate priority. El campo `myTeam` será `undefined` y todos los candidatos se tratan equitativamente.

## Flujo de Procesamiento

### Arquitectura dual: Cloud Function + Client fallback

```
[Jugador envía evaluación]
        │
        ▼
[evaluationSubmissions/{id}]  ← Documento creado en Firestore
        │
        ├──── Cloud Function (primario)
        │     processEvaluationSubmission
        │     Trigger: onDocumentCreated
        │
        └──── Client polling (backup)
              processPendingSubmissions()
              Ejecuta cada 15 segundos en evaluate/page.tsx
```

### Cloud Function: `processEvaluationSubmission`

**Archivo**: `functions/src/triggers/process-evaluation-submission.ts`

Trigger: `onDocumentCreated('evaluationSubmissions/{submissionId}')`

Pasos:
1. Lee la submission
2. Crea `selfEvaluation` si hay goles/asistencias
3. Por cada peer evaluation, crea doc en `evaluations/` y actualiza assignment a `completed`
4. Soft delete: copia a `matches/{matchId}/processedSubmissions/` con metadata
5. Elimina submission original

### Client fallback: `processPendingSubmissions`

**Archivo**: `src/app/matches/[id]/evaluate/page.tsx`

- Se ejecuta vía `setInterval` cada 15 segundos
- Mismo proceso que la Cloud Function
- Si la submission ya no existe (procesada por CF), simplemente la ignora

## Auto-completado de Assignments Pendientes

**Archivo**: `src/app/matches/[id]/evaluate/page.tsx` → `handleFinalizeEvaluation()`

Al finalizar la evaluación, antes de calcular OVRs:

1. Se calcula el **rating promedio global** de todas las evaluaciones de tipo "points" del partido
2. Para cada assignment con status `pending`:
   - Se crea una evaluación sintética con el promedio del partido
   - Se marca con `autoGenerated: true`
   - Se actualiza el assignment a `completed` con `autoCompleted: true`
   - Se agrega a `peerEvalsByPlayer` para que se procese en el loop de OVR

Esto garantiza que **todos los jugadores** reciban alguna evaluación, incluso si algunos evaluadores no completaron sus asignaciones.

## Fórmulas de Progresión de OVR

### OVR Change desde Points

```typescript
ovrChange = (avgRating - 5) * scale
```

| OVR actual | Scale | Descripción |
|------------|-------|-------------|
| < 50       | 0.50  | Very Fast (Rookie) |
| 50-59      | 0.40  | Fast |
| 60-69      | 0.30  | Standard |
| 70-79      | 0.20  | Harder |
| 80-89      | 0.10  | Elite Grind |
| ≥ 90       | 0.05  | Legend (Very slow) |

**Límite**: ±1.5 MAX_STEP

### Distribución de puntos por posición

Los puntos de atributos se distribuyen según pesos por posición:

| Posición | pac  | sho  | pas  | dri  | def  | phy  |
|----------|------|------|------|------|------|------|
| DEL      | 0.25 | 0.35 | 0.15 | 0.15 | 0.05 | 0.05 |
| MED      | 0.15 | 0.15 | 0.30 | 0.20 | 0.10 | 0.10 |
| DEF      | 0.15 | 0.05 | 0.15 | 0.05 | 0.40 | 0.20 |
| POR      | 0.10 | 0.05 | 0.10 | 0.05 | 0.50 | 0.20 |

Se usa **error accumulation (dithering)** para evitar sesgo de redondeo.

### Diminishing Returns (Tags y AI Text)

Aplica a cambios de atributos individuales:

| Valor actual | Multiplier | Efecto |
|-------------|------------|--------|
| ≥ 92        | 0.1        | 10% efectivo (Legend) |
| 85-91       | 0.2        | 20% efectivo (Elite) |
| 75-84       | 0.4        | 40% efectivo (Star) |
| 60-74       | 0.7        | 70% efectivo (Pro) |
| < 60        | 1.0        | 100% efectivo |

```
newValue = currentValue + (baseChange * multiplier)
```

## Fallback "Anti-Paja" (Sin evaluaciones)

Si un jugador no recibe evaluaciones de tipo "points":

| Condición | Rating inferido |
|-----------|----------------|
| ≥ 2 goles OR ≥ 2 asistencias OR (goles + asistencias ≥ 3) | 8 |
| 1 gol OR 1 asistencia | 7 |
| Sin stats, sin votos | 5 (neutral) |

## Post-acciones por Tipo de Partido

### Partido Normal (`friendly`)
- Actualiza OVR, atributos, stats
- Publica actividades sociales
- Registra historial de OVR

### Partido de Liga (`league`)
- Todo lo anterior +
- `updateLeagueStandingsAction()` actualiza la tabla de posiciones

### Partido de Copa (`cup`)
- Todo lo anterior +
- `advanceCupWinnerAction()` avanza al ganador en el bracket
- Si hay empate, no se avanza automáticamente

## Colecciones Firestore

| Colección | Descripción |
|-----------|-------------|
| `evaluationSubmissions/{id}` | Submissions pendientes de procesar |
| `evaluations/{id}` | Evaluaciones peer procesadas |
| `matches/{matchId}/assignments/{id}` | Asignaciones evaluador → sujeto |
| `matches/{matchId}/selfEvaluations/{id}` | Auto-evaluaciones (goles, asistencias) |
| `matches/{matchId}/processedSubmissions/{id}` | Audit trail de submissions procesadas |
| `players/{id}/ovrHistory/{id}` | Historial de cambios de OVR |

### Campos clave de Assignment

```typescript
{
  matchId: string;
  evaluatorId: string;    // Quién evalúa
  subjectId: string;      // A quién evalúa
  status: 'pending' | 'completed';
  evaluationId?: string;  // ID del doc en evaluations/
  autoCompleted?: boolean; // true si fue completado automáticamente
}
```

### Campos clave de Evaluation

```typescript
{
  assignmentId: string;
  playerId: string;       // Sujeto evaluado
  evaluatorId: string;
  matchId: string;
  rating?: number;        // Points type
  performanceTags?: PerformanceTag[]; // Tags type
  textDescription?: string;          // Text type
  aiAttributeChanges?: AttributeChange[]; // Text type (AI)
  aiConfidence?: number;
  aiSummary?: string;
  autoGenerated?: boolean; // true si fue creado por auto-completado
  evaluatedAt: string;
}
```
